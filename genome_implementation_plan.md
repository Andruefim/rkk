# Genome-Driven Priors Generation (Systematic Biological Initialization)

Полностью согласен с вашей оценкой. Попытка дистиллировать всё с нуля (от удержания равновесия до высокоуровневого планирования) в "чистую" нейросеть через временную эволюцию — задача с астрономическим пространством поиска. Биологические системы так не работают: детеныши многих млекопитающих встают на ноги через несколько часов после рождения благодаря жестко зашитым приорным структурам (Central Pattern Generators, врожденные рефлексы, пре-монтированная зрительная кора).

Идея дать гуманоиду **сильный "Геном" (Priors)**, сгенерированный LLM — это мощный и правильный сдвиг архитектуры.

## Open Questions

> [!WARNING]
> 1. **Формат приоров**: Как именно мы хотим применять эти приоры к графу (GNN)? Это будут веса конкретных связей (например, жесткие синапсы между ногами для CPG), или это отдельные хардкод-модули (Sub-networks), которые GNN просто вызывает/модулирует?
> 2. **Какая LLM будет использоваться для генерации?** Будем ли мы использовать мощную облачную модель (через API) один раз (offline generation) для создания генома, или это будет делать локальный учитель (Ollama) динамически? Я рекомендую **Offline генерацию скриптом**, так как это разовая сложная задача, требующая сильных reasoning способностей (как у GPT-4 или Gemini 3).

## Proposed Changes

Мы создадим систему **Genome Builder**, которая будет работать как пайплайн: `Prompt -> Generate -> Verify Schema/Topology -> Fix -> Save JSON/YAML`.

### [Genome Builder Pipeline]

Создание нового набора скриптов для систематической генерации приоров. Будет использоваться пара агентов: **Generator** и **Verifier**.

#### [NEW] [backend/engine/genome/builder.py](file:///c:/Users/Andrey/Desktop/agi/rkk/backend/engine/genome/builder.py)
Оркестратор. Запускает генерацию по частям, передает результаты верификатору, и просит генератор исправить ошибки (self-correction loop).

#### [NEW] [backend/engine/genome/schemas.py](file:///c:/Users/Andrey/Desktop/agi/rkk/backend/engine/genome/schemas.py)
Pydantic-схемы для каждого модуля (Motor, Vision, Executive). Это позволит строго валидировать формат, который выдает LLM (проверять наличие нужных полей, типы данных, диапазоны).

#### [NEW] [backend/engine/genome/prompts.py](file:///c:/Users/Andrey/Desktop/agi/rkk/backend/engine/genome/prompts.py)
Библиотека системных промптов для каждой части приоров:
- **Motor / Cerebellum**: CPG матрицы (ритмы шага), рефлексы (выставление рук при падении), ПИД-коэффициенты для суставов.
- **Vision / Cortex**: Матрицы сверток или графы внимания для выделения контуров, препятствий, горизонта.
- **Drives / Hypothalamus**: Базовые веса гомеостаза (усталость, боль от ударов, награда за высоту головы).
- **Language / Wernicke-Broca**: Маппинг базовых токенов в физические концепты (например, "ВСТАТЬ" -> активация Motor_Stand).

### [GNN Integration]

Загрузка сгенерированных приоров в текущий System 2 / Causal Graph при инициализации симуляции.
